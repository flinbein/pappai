# Общий MCP OAuth профиля и личный MCP OAuth приложения

Запуск с Node.js и исполняемым файлом Codex CLI 0.170.0 в PowerShell

```powershell
node tests/probes/codex-oauth/probe.mjs (Get-Command codex.exe).Source
```

В Linux последний аргумент — путь к бинарному файлу Codex. Пробу можно выполнить в контейнере с `--network none`. HTTP-провайдер и шлюз слушают случайные порты loopback. Все три нативных OAuth-входа используют PKCE и вымышленные учётные записи. Новый временный каталог содержит отдельные `CODEX_HOME` и удаляется при выходе. Вызовов модели нет.

Два App Server одновременно вызывают `whoami` через `mcpServer/tool/call`. Личный сервер у обоих имеет одно имя и URL. Нативный файл авторизации APP A даёт `alice`, у APP B — `bob`. Для общего сервера оба обращаются к локальному шлюзу, который проверяет ключ исполнителя и вызывает `whoami` через один профильный App Server. У этого процесса собственный файл авторизации, и провайдер видит `team`. У пустого профиля инструменты недоступны. Ключ A на маршруте B получает HTTP 403.

Тест ускоряет истечение срока только в синтетических файлах при остановленных процессах. Провайдер однократно принимает каждый refresh token и сразу отзывает прежнюю пару токенов. Каждый из трёх владельцев переживает перезапуск и две последовательных ротации. Прежняя копия файла профиля получает `invalid_grant`. В отдельной проверке провайдер отзывает действующий access token профиля, пока оба исполнителя работают. Тест требует, чтобы два одновременных вызова завершились успешно после одного общего обновления.

Шлюз обслуживает один синтетический инструмент и проверяет принадлежность маршрута. Совместимость полноценного шлюза с MCP-ресурсами, промптами, потоковыми ответами, подтверждениями и разными OAuth-провайдерами требует отдельных проверок. Файловые права, доставку ключа шлюза и изоляцию команд агента эта проба не проверяет.
