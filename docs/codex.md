# Запустить APP с Codex

Установите [пакет и дистрибутив CLI](https://github.com/flinbein/pappai-runner-codex#установка) и зарегистрируйте внешний раннер на workspace через `$.runners.add`. Регистрация требует неограниченных прав. Для каталога авторизации профилей и состояния раннера смонтируйте отдельный постоянный том в `/run/pappai/private`. APP получает доступ к своей авторизации по ID профиля.

| На какой ноде вызвать | Метод | Пример аргументов |
|---|---|---|
| Workspace или TEAM | `$.profile.create` | `{"name":"shared","permissions":null}` |
| Созданный PROFILE | `codex.setup` | `{"authFile":"/tmp/codex-auth.json"}` |
| Workspace или TEAM | `$.app.create` | Укажите имя, права APP, ID в `profile` и манифест в `source.manifest` |
| PROFILE | `$.profile.scope.set` | `{"scope":["ID_APP"]}` с ID созданной APP |
| PROFILE | `$.profile.enable` | `{}` |
| APP | `$.app.start` | `{}` |
| APP | `agent.execute` | `{"input":"Составь краткое резюме текста …"}` |

Файл для `codex.setup` читается по файловым правам вызывающего. У песочного USER путь `/tmp` соответствует его временному каталогу. Через `codex.status({})` удобно проверить результат импорта. Для отзыва сначала отключите профиль через `$.profile.disable`, затем удалите сохранённое подключение через `codex.remove`. Чтобы снова запустить APP, которой отказали в доступе, восстановите авторизацию и `scope`, включите профиль и вызовите `$.app.start`.

[Примеры манифестов](https://github.com/flinbein/pappai-runner-codex/tree/master/examples) объявляют метод `agent.execute`. Одноразовый режим возвращает результат одного поручения. Постоянный режим сохраняет диалог между запусками исполнителя. Контроллер проверяет отправителя, разрешение на метод и объявленную схему. Для рабочих операций от имени агента действуют одновременно права APP и PROFILE. Подробности доступны в [профилях](dev/runners/profiles.md) и [описании раннера](dev/runners/codex.md).
