# Управление APP

Войдите в панель как администратор и нажмите имя APP в списке нод. Карточка показывает статус, последнюю проблему, число занятых слотов и количество ожидающих вызовов. **Обновить состояние** запрашивает свежие значения и сохраняет введённый в редактор текст.

**Остановить** закрывает приём вызовов. Вызовы из очереди сразу получают ошибку. Активный процесс получает SIGINT и может успеть отправить ответ. Через десять секунд раннер посылает ещё работающему процессу SIGKILL. Статус `stopping` означает, что завершение ещё ожидается. После остановки нажмите **Запустить**, чтобы APP снова принимала вызовы. Процесс запускается при первом назначении.

Чтобы изменить команду, аргументы или контракт, отредактируйте **Манифест JSON** и нажмите **Сохранить манифест**. Панель покажет ошибку, если команду или схему нельзя принять. Успешное сохранение сразу обновляет `help` и настройки будущих процессов. Статус APP сохраняется. Уже запущенный процесс заканчивает свою работу с прежними аргументами, его ответ проверяется по действующей схеме.

Эти же операции доступны администратору через `call`.

| Метод | Параметры `data` | Результат |
|---|---|---|
| `$.app.get` | `{}` | `status`, `lastIssue`, `manifestChanged`. Для встроенного манифеста последнее поле равно `false`. |
| `$.app.executors.get` | `{}` | `mode`, `active`, `limit`, `queued`, `restarting`. Вызов в занятом слоте уже исключён из `queued`. |
| `$.app.stop`, `$.app.start` | `{}` | `{}` после принятия команды. Итог остановки можно прочитать через `$.app.get`. |
| `$.app.manifest.get` | `{}` | Источник в виде `{manifest}`. |
| `$.app.manifest.getApplied` | `{}` | Применённый манифест целиком. |
| `$.app.manifest.set` | `{source: {manifest: …}}` | `{}` после проверки и сохранения полного манифеста. |
