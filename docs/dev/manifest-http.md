# Файловый источник и HTTP-сокет APP

Контроллер хранит источник и применённый JSON в SQLite. При создании он получает ID остановленной APP внутри savepoint, читает файл с её эффективными правами, проверяет схему и публикует конфигурацию. Ошибка возвращает базу к состоянию до вызова. Старые записи с одним манифестом читаются как встроенные источники. Секреты хранятся в закрытой базе платформы. Ее резервная копия также содержит секреты.

Один наблюдатель на путь обслуживает все связанные APP. Раз в 250 мс он проверяет имя, идентификаторы файла и ссылки, размер и времена изменений. Первый проход также перечитывает источник, чтобы учесть замену между первоначальным чтением и подключением наблюдателя. При изменении следующий проход проверяет данные и права отдельно для каждой APP. При восстановлении контроллер подключает наблюдателей и перечитывает файлы. Применённая конфигурация определяет `help`, подписки и назначения. При работающем постоянном процессе контроллер удерживает последний проверенный вариант до выхода исполнителя.

Прокси ищет APP по публичному имени. Контроллер проверяет статус, пермит и текущий экземпляр. Приватный каталог каждого процесса монтируется отдельно. Путь внутри песочницы — `/run/pappai/http/app.sock`. На Linux прокси открывает inode сокета с `O_PATH | O_NOFOLLOW`, проверяет тип и подключается через `/proc/self/fd`. Замена имени во время подключения не позволяет перенаправить прокси на другой сокет. После отзыва маршрута уже открытый поток может завершиться на прежнем процессе. По HTTP прокси удаляет cookie панели из запроса, доменные cookie и cookie с именами панели из ответа.
