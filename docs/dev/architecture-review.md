# Устройство контроллера

## Завершение вызова

Контроллер хранит открытый вызов под системным ID. Очередь APP содержит эти ID, а раннер получает ID своего назначения. Ответ, отмена, таймаут и потеря раннера сходятся в одной операции завершения. Первый окончательный исход удаляет запись и снимает таймер. Поздний ответ получает ошибку. Если успешный ответ нарушает выходную схему, контроллер оставляет вызов открытым для исправления.

Завершение вызова и освобождение слота — разные операции. Например, клиент уже получил ошибку по таймауту, но процесс ещё работает. Следующее назначение ждёт выхода этого процесса. [Реализация](../../src/controller.ts) · [Проверки гонок](../../tests/controller.test.ts)

## Конфигурация исполнителя

Контроллер проверяет встроенный JSON-манифест при создании APP и кеширует подготовленную конфигурацию. Из неё он получает описания для `help`, валидаторы и настройки процесса. При назначении работы контроллер вычисляет эффективные права и передаёт раннеру профиль песочницы. [Подготовка манифеста](../../src/manifest.ts) · [Запуск процесса](runners/process.md)

Замена встроенного манифеста синхронна. До записи в SQLite контроллер готовит новую конфигурацию и проверяет очередь этой APP. Исчезнувший метод, несовместимый вход и несовпадение запрошенной версии завершают ожидающий вызов ошибкой. У назначенного вызова контроллер проверяет, существует ли ещё метод. Если он сохранился, исполнитель может ответить по актуальной выходной схеме. После записи контроллер меняет кеш и отклоняет несовместимые вызовы до следующей выдачи работы.

При ручной остановке занятый слот сохраняется до выхода процесса. Если спустя секунду после SIGKILL подтверждения выхода всё ещё нет, раннер закрывает потоки процесса, освобождает слот и сообщает об ошибке. Если контроллер аварийно завершился в состоянии `stopping`, при следующем запуске APP получает статус `error` с пояснением в `lastIssue`.

## Файловые пакеты в плане v1

При добавлении файловых манифестов право установки из доверенного каталога будет включать доверие к обновлениям издателя, в том числе к смене раннера. Активировать подготовленный контракт и настройки запуска потребуется вместе, чтобы описание метода и следующее назначение соответствовали одной версии конфигурации. [План разработки](roadmap.md)
