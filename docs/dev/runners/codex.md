# Установка раннера Codex и CLI

Раннер разрабатывается в отдельном репозитории `pappai-runner-codex` и поставляется как npm-пакет. Версии раннера и Codex CLI администратор выбирает независимо. Поддержка административной конфигурации раннера в API pappai запланирована.

| Компонент | Где хранить в контейнере | Кто настраивает |
|---|---|---|
| Пакет раннера и его зависимости | Например, `/var/lib/pappai/runners/codex/<версия>/` на постоянном томе | Администратор регистрирует абсолютный путь к точке входа в [реестре](registry.md) |
| Дистрибутив Codex CLI для ОС и архитектуры контейнера | Например, `/var/lib/pappai/tools/codex/<версия>/` на постоянном томе | Администратор задаёт абсолютный `codexExecutablePath` в конфигурации установленного раннера |
| Учётные данные, история и MCP | В служебных хранилищах с отдельным владельцем для каждого вида данных | [PROFILE](profiles.md) предоставляет подключение, APP владеет своей историей и локальными MCP |

Путь на постоянном томе переживает замену контейнера при повторном подключении тома к тому же пути. Обычный каталог образа, включая `/opt`, получает такое свойство только при отдельном монтировании. Дистрибутив нужно переносить целиком с поставляемыми ресурсами и утилитами. Для установки из npm сохраняют также обёртку и её платформенную зависимость, если точкой запуска выбрана обёртка.

Предлагаемое поле административной конфигурации — `config.codexExecutablePath`. Действующая `$.runners.add` умеет регистрировать `entrypoint` и `settingsSchema`. Для доверенной конфигурации потребуется расширить регистрацию и IPC. Записывать конфигурацию, исполняемые файлы и их родительские каталоги может только администратор. Владельцу APP и PROFILE путь к CLI через манифест, override, профиль или переменные окружения не делегируется.

## Обновление

1. Установить раннер или полный CLI в новый версионный каталог. Сохранить предыдущий комплект до завершения проверки.
2. В целевом образе запустить выбранный CLI по абсолютному пути, проверить `--version` и обмен `initialize` с `codex app-server`. Изменения CLI могут потребовать повторной проверки MCP и песочницы.
3. Переключить административный путь и перезапустить раннер через `$.runners.restart`. При откате вернуть путь к предыдущей совместимой версии и повторить перезапуск.

## Что проверено

На Alpine Linux x86_64 с Codex CLI 0.170.0 тестовый внешний раннер установили из архива `npm pack` на постоянный том. Через настоящий реестр pappai создали APP и вызвали её метод. Раннер запустил CLI по абсолютному пути и получил ответ app-server на `initialize`. После удаления тестового контейнера новый контейнер с тем же томом повторил вызов для прежней APP без переустановки и повторной регистрации. Путь в этом тесте читал сам тестовый раннер из доверенного файла. Передача административной конфигурации через контроллер остаётся задачей реализации.

В [проверке истории](../../../tests/probes/codex-sessions/README.md) два app-server использовали общую тестовую авторизацию Codex и раздельные каталоги состояния. После пересоздания контейнера каждый восстановил свой диалог и продолжил его с прежним контекстом. Даже при известном ID открыть чужой диалог через `thread/resume` не удалось. Проверка использует локальную модель-имитатор и авторизацию API-ключом. Защита файлов от прямого чтения командами APP проверяется отдельно при интеграции.
