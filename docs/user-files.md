# Файлы USER в панели

После входа откройте `/files/` на том же адресе, что и панель. Каталоги отображаются как страницы со ссылками. Обычный файл можно скачать, включая файлы HTML. Для получения из скрипта панели используйте `fetch` с той же сессией.

```js
const response = await fetch('/files/workspace/reports/today.txt');
if (response.ok) {
  const path = decodeURIComponent(response.headers.get('X-Pappai-File-Path'));
  console.log(path, await response.text());
}
```

Страница показывает ветки, к которым USER имеет доступ через собственные пермиты, родителей или членство в TEAM. Если выдан один файл, путь к нему виден от корня. Промежуточная страница показывает только ведущие к разрешённым существующим объектам имена. В доступной физической директории видны также символические ссылки. При переходе сервер проверяет полномочия на запрошенное имя и на цель ссылки.

Для USER с песочницей `/tmp` соответствует его личному каталогу, для USER без песочницы — каталогу контейнера. Деревья `/proc`, `/dev`, `/sys` и `/run` закрыты. Код `403` означает отсутствие доступа, `404` — отсутствие объекта по разрешённому пути. Некорректный путь возвращает `400`, ошибка подготовки среды или чтения может привести к ошибке сервера.

Права фиксируются при каждом запросе. Начатое скачивание продолжается при изменении пермитов или завершении сессии. Следующий запрос использует актуальные права. Делегирование между двумя APP описано отдельно. [Файлы в вызове](delegated-files.md)
